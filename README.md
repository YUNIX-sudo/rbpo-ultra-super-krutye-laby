## лабораторная работа №1
реализованы три костыльных эндпоинта через REST контролеер фреймворка SpringBoot:
* **'GET /'** -> сообщение :)
* **'GET /randomnumbers'** -> рандомное число
* **'GET /{шо угодно}'** -> эхо сервер

## лабораторная работа №2 (17 вариант)
тут уже не три эндпоинта, а нормальный REST API

для пяти сущностей сделаны все 5 операций (GET, GET/{id}, POST, PATCH, DELETE):
* **'/api/users'** -> пользователи (координаторы и волонтеры)
* **'/api/volunteer-campaigns'** -> акции помощи (даты, координатор, статус)
* **'/api/volunteer-tasks'** -> задачи акции (число людей, старт, длительность в часах)
* **'/api/volunteer-responses'** -> отклики волонтеров на задачи
* **'/api/participation-reports'** -> отчеты об участии (часы работы и подтверждение)

также все по тз: статус коды, время задется сервером

## лабораторная работа 3




бизнес операции
1. **регистрация волонтера на задачу**: волонтер может записаться на задачу, если кампания еще не завершена и у него роль `VOLUNTEER`
2. **завершение кампании**: координатор переводит кампанию в статус `FINISHED`.
3. **подтверждение участия**: координатор подтверждает отчет волонтера, что автоматически помечает его отклик как `COMPLETED`
4. **назначение координатора**: возможность сменить ответственного за кампанию (только на пользователя с ролью `COORDINATOR`)
5. **деактивация пользователя**: при деактивации пользователя все его активные отклики автоматически отменяются (`CANCELLED`)

завернул все в докер, бд - постгрес


- `/api/volunteer-responses/register?taskId=1&volunteerId=2` -> регистрация волонтера
- `/api/volunteer-campaigns/{id}/finish` -> завершение кампании
- `/api/participation-reports/{id}/confirm?status=CONFIRMED` -> подтверждение участия
